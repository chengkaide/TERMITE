# 数据导入

TERMITE 原本只认一种文件格式（"Intensity Vs Time" 的 CSV，表头在第 3 行、
数据在第 4 行、12 个同位素）。真实数据远不止这一种，本文说明导入层是怎么做的。

---

## 1. 支持的格式

导入层靠**内容匹配**定位表头与数据行，不依赖固定行号。
`termite_probe(path)` 会逐个文件识别，返回格式名、分隔符、表头行、
数据起始行、同位素个数、同位素写法、样品名。

### Qtegra（Thermo iCAP RQ / iCAP TQ）—— 新增

```
第 1 行      SRM 610:08/06/2023 03:07:07 AM;      ← 样品名:日期 时间;
第 2–13 行   仪器元数据（Software / Configuration / STD / RF / Ion Optics …）
第 14 行     表头：Time,7Li,9Be,11B,…,208Pb,209Bi,232Th,238U,   ← 末尾多一个逗号
第 15 行     每通道元数据：,dwell time=0.01;xcal factor=53845.6,…  ← 自动跳过
第 16 行起   数值数据（**计数率 cps**，Qtegra 已按 dwell time 换算好）
```

- **表头行不固定**：程序找的是「第 1 个字段以 `time` 开头、且至少有 3 列」的那一行。
  不同批次元数据行数不同也没关系。
- **第 15 行（dwell/xcal）不写死行号**：程序找的是「字段数对得上、且第 2 个字段
  能转成数字」的第一行。数值行之前的任何非数值行都会被自然跳过。
- **样品名**取自第 1 行冒号之前的内容。判据是「冒号后面跟日期」，
  不会把普通含冒号的路径误当样品名。
- Qtegra 的同位素写法是 **质量数在前**（`25Mg`），TERMITE 的参考表用的是
  **元素在前**（`Mg25`）。导入层统一规范化，两边都能用。

### Agilent / 四极杆（TERMITE 原始示例）

```
第 1–2 行    采集信息
第 3 行      表头：Time [Sec],Mg25,Al27,…
第 4 行起    数据，逗号分隔
```

### Element2 / SF-ICP-MS

结构与 Agilent 相同，但**分隔符是制表符**，表头带分辨率后缀（`Ca43(LR)`），
由 `resolution` 参数剥掉。

### 其它

只要文件里存在一行以 `Time` 开头、后面跟同位素名的表头，且其下有数值行，
就能被识别（`format = "generic"`）。分隔符在 `,` `\t` `;` 三者中自动选。

## 2. 文件怎么分类：样品 / 定标参考 / 质量监控

两种布局（界面上的「目录组织方式」）：

| 布局 | 说明 |
|---|---|
| `dir` | **样品与参考物质分目录**（TERMITE 原始布局）。参考物质按**文件名**里的名称匹配。 |
| `flat` | **同一目录混放**（Qtegra 常见）。每个文件先解析出样品名，再去匹配名单。 |

`flat` 布局下的分类规则：

- 样品名落在 **参与定标的参考物质** 名单里 → `ref`
- 落在 **质量监控样品** 名单里 → `qc`
- 其余全部 → `sample`

名单**之外**的文件一律算样品，所以名单要填全，否则监控标样会被当成样品混进结果。

### 定标参考 vs 质量监控，为什么要分开？

一批数据的测定顺序通常是
`SRM610 → SRM612 → BIR-1G → BCR-2G → BHVO-2G → 样品…`，
前三/五个里，**SRM610/612 是定标用的**，后三个是**监控用的**。

- `ref`（定标参考）参与 RSF 计算，进结果表的浓度换算。
- `qc`（质量监控）**不参与 RSF**，只报回收率。
  混进定标会把基体不同的标样带进标定曲线，引入偏差。

界面上这两类是分开填的。

### 名称对不上怎么办：别名表

仪器里的标样名和 GeoReM 的命名经常不一致：

| 仪器里 | 参考表里的行名 |
|---|---|
| `SRM 610` | `NIST610` |
| `SRM 612` | `NIST612` |
| `MACS-3` | `MACS3` |
| `StHs6/80-G` | `StHs` |

`TERMITEScriptFolder/ReferenceMaterial_aliases.csv` 负责这笔映射（`别名,目标` 两列，
`#` 开头是注释）。填名单时可以直接用仪器里的写法。

## 3. 同位素别名表

`TERMITEScriptFolder/Isotope_aliases.csv` 处理「测到的同位素在参考表里查不到」。

目前已知一处：**`In115`**。TERMITE 自带的 `AtomGewIsoAbund_NIST.csv` 与
`Standards_GeoReM.csv` 里写的是 `In116`，但：

- 铟天然只有 **In-113（4.29%）** 与 **In-115（95.71%）** 两个稳定同位素，
  不存在天然 In-116；
- 表中 `In116` 的丰度恰为 **0.9571**，原子量 114.818 —— 与 In-115 完全一致。

可判定 `In116` 是 `In115` 的笔误。别名表里把 `In115` 指向 `In116` 列，
**不改动上游数据文件**，映射原因写在表里的注释中。

若某个同位素在别名表里也找不到，程序会退一步借用**同元素的其他同位素**列并给出警告。
这是合理的：推荐值表按**元素含量**填写，同一元素的各同位素列取值相同。
但这属于兜底，看到警告应该去补别名表。

## 4. 内标怎么选

内标元素必须**在样品里含量已知且分布均匀**。同一个批次里基体不同时，
一个内标套不住全部。

界面上「下载/预览」里有 **「计算主量同位素」**：
它读每个文件在信号窗内的净计数，列出最高的几个同位素。
一眼就能看出这批样品属于哪一类。例如实测某批次：

```
182W  40 个文件      ← 全部是白钨矿（CaWO4），W 是主量元素
27Al  15 个文件      ← BIR-1G / BCR-2G / BHVO-2G 三个玄武岩玻璃
23Na  10 个文件      ← SRM 610 / SRM 612
```

据此把内标设为 `182W`、样品内标含量按 CaWO4 化学计量取 638 500 µg/g。
如果结果显示样品分成好几类基体，用「样品名过滤」分批处理。

> 注意：内标元素自己输出的浓度**恒等于你输入的 `C_IS`**，
> 它不是测出来的，只起归一化作用。

## 5. 命令行用法（不启动 Shiny）

```bash
Rscript tools/run_termite.R \
  --dir  "<数据目录>" \
  --layout flat --auto \
  --ref  "SRM 610,SRM 612" \
  --qc   "BIR-1G,BCR-2G,BHVO-2G" \
  --is   182W --is-conc 638500 \
  --blank 25,60 --signal 70,118 \
  --out  "<输出目录>"
```

输出到 `<输出目录>`：`Results_*.csv`、`LoD_*.csv`、`RSFused_*.csv`、
`Recovery_*.csv`、`MainIsotope_*.csv`、`Plots_*.pdf`、`运行参数.txt`。
`--is` 接受同位素名，程序会自己换算成列号。

## 6. 参考物质推荐值缺失时

`Standards_GeoReM.csv` 只带 12 种物质：ATHO-G、BAM-B、KL2-G、MACS1、MACS3、
NIST610、NIST612、StHs、T1-G、GSD-G、N610、N612。

**USGS 的三个玄武岩玻璃（BIR-1G、BCR-2G、BHVO-2G）不在里面。**
它们通常只作质量监控，不参与定标，所以不影响浓度结果 ——
但 `Recovery_*.csv` 里对应的回收率会是 `NA`，程序也会给出明确警告。

需要这几行的话，从 [georem.earth](https://georem.earth/) 取 preferred values，
按 `Standards_GeoReM.csv` 的列顺序补进去即可（第一列是物质名，
其余列是**同位素名**，按元素含量填写）。
补完之后同样一批数据不用改动其它任何设置，回收率就会出来。
